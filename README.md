# Telegram OCR Bot

Telegram-бот принимает фото, изображения и PDF, распознаёт русский и английский печатный текст
локально (PaddleOCR), при необходимости проверяет результат с помощью ИИ и возвращает файл Word (`.docx`).

Реализация по [ТЗ](docs/ТЗ_Telegram_OCR_Bot.md). Целевая нагрузка — до 50 страниц в сутки.

## Возможности

- Команды `/start` (`/help`) и `/mode`; приём фото, изображений файлом и PDF.
- Форматы: JPEG/JPG, PNG, TIFF/TIF (в том числе многостраничный), WEBP, PDF. Формат определяется
  по содержимому файла и проверкой декодирования, имя и MIME-тип не учитываются.
- Лимиты (настраиваются): 20 МБ на файл, 30 страниц, 40 Мпикс на изображение. Размер проверяется
  до скачивания, число страниц и пиксели — до декодирования и рендеринга. Страницы PDF, которые
  не укладываются в лимит пикселей, рендерятся с пониженным DPI (но не ниже 50 DPI).
- Предобработка: учёт EXIF-ориентации, приведение к RGB/оттенкам серого, постраничная обработка
  с сохранением страниц на диск. Дополнительные шаги для OCR (`contrast`, `denoise`, `binarize`,
  `grayscale`) включаются через `OCR_PREPROCESS` и применяются только к копии для OCR: в DOCX
  попадает исходное изображение.
- OCR: PaddleOCR 3.x (поддерживается и API 2.x), восстановление порядка строк по координатам,
  предупреждения о фрагментах с низкой уверенностью и о страницах без текста.
- AI-проверка (`/mode`):
  - `off` — только локальный OCR, внешний API не вызывается;
  - `text` — модель исправляет очевидные ошибки OCR, не видя оригинала (и не утверждает обратного);
  - `image` — модель сверяет изображение страницы с OCR-текстом.

  Ответ модели проверяется схемой Pydantic (`corrected_text`, `warnings`, `needs_review`). Если модель
  возвращает пустой текст, сильно меняет объём текста или «находит» текст там, где OCR не нашёл
  ничего, правка отклоняется: остаётся текст OCR, а фрагмент помечается для ручной проверки.
  При сбое API документ всё равно формируется, но в DOCX и в подписи к нему указано, что текст
  **не проверен**.
- DOCX: `facsimile` (по умолчанию) — страницы как изображения с сохранением пропорций и ориентации,
  затем раздел «Распознанный текст» по страницам; `editable` — только текст, страницы разделены
  разрывами, каждая строка в отдельном абзаце. В документе указан статус проверки каждой страницы.
- Пачка файлов: файлы, присланные подряд (альбом или несколько альбомов по 10), собираются
  в один многостраничный DOCX и обрабатываются по порядку отправки. Если на страницах есть номера
  в колонтитулах («- 3 -», «Стр. 3», «3 из 10», «Page 3»), страницы упорядочиваются по ним;
  многостраничные файлы при этом не разрываются. Следующие задания пользователя ставятся в очередь.
- Примечания Word на полях исключаются из текста, а изображение страницы обрезается. Область
  примечаний находится по серой полосе с выносками («Добавлено примечание [ПП1]»), а на фото
  экрана — по колонке мелкого текста справа от документа. Аннотации PDF не рендерятся.
- Таблицы с границами восстанавливаются как таблицы Word, включая объединённые ячейки. Сетка
  находится по линиям на изображении, текст распределяется по ячейкам. В AI-режимах ячейки
  исправляются отдельно, а структура таблицы защищена: если ИИ её меняет, правки отклоняются.
  Таблицы без границ остаются текстом. Линии сетки ищутся с учётом наклона и перспективы
  (фото под углом). Цветные подчёркивания исправлений Word не считаются границами. Перед OCR
  линии таблицы стираются с копии изображения, чтобы детектор не терял прижатый к ним текст.
  Наклон страницы выравнивается (до 10°).
- Предупреждения отправляются отдельным сообщением после DOCX.
- Allowlist по Telegram user ID проверяется для всех сообщений и нажатий кнопок.

**Ограничения.** Таблицы без границ и многоколоночная вёрстка не восстанавливаются как объекты Word. Рукописный текст не поддерживается. OCR и ИИ могут
ошибаться: ФИО, даты, суммы и реквизиты нужно сверять вручную.

## Структура

```text
app/
  bot.py                  точка входа, логирование с маскированием секретов, сборка Dispatcher
  config.py               настройки из .env (pydantic-settings)
  handlers.py             Telegram-слой: команды, /mode, allowlist, приём файлов, ответы
  models.py               модели данных и схема ответа ИИ
  services/
    file_parser.py        проверка формата и лимитов, изображения/PDF → PNG-страницы
    preprocessing.py      расширяемая предобработка для OCR
    ocr_engine.py         PaddleOCR (API 2.x/3.x), порядок чтения
    ai_validator.py       AI-проверка (OpenAI), защитные правила
    document_builder.py   генерация DOCX (facsimile / editable)
    pipeline.py           оркестрация задания, временный каталог, очистка
tests/                    модульные и интеграционные тесты
deploy/                   unit-файл systemd
Dockerfile, docker-compose.yml
```

Тяжёлые операции (разбор файла, OCR, генерация DOCX) выполняются в отдельном потоке
(`asyncio.to_thread`), поэтому event loop бота не блокируется. Одновременно выполняется не больше
`MAX_CONCURRENT_JOBS` заданий, у одного пользователя — одно задание за раз.

## Требования

- Linux VPS (рекомендуется Ubuntu 22.04/24.04 LTS), Python 3.11.
- 2–4 vCPU, 4–8 ГБ RAM. Пик памяти при OCR одной страницы — около 1 ГБ.
- Исходящий HTTPS к `api.telegram.org`; при AI-проверке — к `api.openai.com`.
- При первом запуске PaddleOCR скачивает модели (~200 МБ) в `~/.paddlex`.

## Установка на VPS

```bash
sudo apt update
sudo apt install -y python3.11 python3.11-venv libgl1 libglib2.0-0 libgomp1 git
sudo useradd --system --create-home --shell /usr/sbin/nologin ocrbot
sudo git clone <repository-url> /opt/ocr_telegram_bot
sudo chown -R ocrbot:ocrbot /opt/ocr_telegram_bot
cd /opt/ocr_telegram_bot
sudo -u ocrbot python3.11 -m venv .venv
sudo -u ocrbot .venv/bin/pip install --upgrade pip
sudo -u ocrbot .venv/bin/pip install -r requirements-dev.txt   # для production без тестов: requirements.txt
sudo -u ocrbot cp .env.example .env
sudo -u ocrbot chmod 600 .env
sudo -u ocrbot nano .env
```

Если в образе Ubuntu нет `python3.11`, используйте Docker (см. ниже) или установите Python 3.11
из доверенного источника.

## Настройка `.env`

Обязателен только `TELEGRAM_BOT_TOKEN`. Полный список с комментариями — в [.env.example](.env.example).

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | — | токен от @BotFather |
| `ALLOWED_TELEGRAM_USER_IDS` | пусто | разрешённые user ID через запятую; пусто — бот доступен всем |
| `OPENAI_API_KEY` | пусто | без ключа режимы `text`/`image` недоступны |
| `OPENAI_MODEL` | `gpt-4.1-mini` | модель с поддержкой изображений и JSON-ответа |
| `OPENROUTER_API_KEY`, `OPENROUTER_MODEL` | пусто, `openai/gpt-4.1-mini` | OpenRouter, если `OPENAI_API_KEY` пуст |
| `AI_PROVIDER` | `auto` | `auto` / `openai` / `openrouter` |
| `OPENAI_TIMEOUT_SECONDS`, `OPENAI_MAX_RETRIES` | `60`, `2` | тайм-аут и повторы запросов к API |
| `AI_VALIDATION_MODE` | `off` | режим по умолчанию: `off` / `text` / `image` |
| `DOCX_MODE` | `facsimile` | `facsimile` / `editable` |
| `OCR_LANGUAGES` | `ru,en` | языки OCR |
| `OCR_MIN_CONFIDENCE` | `0.6` | порог уверенности для предупреждений |
| `OCR_PREPROCESS` | пусто | шаги предобработки: `grayscale,contrast,denoise,binarize` |
| `OCR_DET_MODEL`, `OCR_REC_MODEL` | `PP-OCRv5_mobile_det`, авто | модели PaddleOCR (см. «Совместимость») |
| `OCR_ENABLE_MKLDNN` | `false` | ускорение oneDNN на CPU (включать после проверки) |
| `MAX_UPLOAD_MB` / `MAX_PDF_PAGES` / `MAX_IMAGE_PIXELS` | `20` / `30` / `40000000` | лимиты |
| `PDF_DPI` | `200` | разрешение рендера PDF |
| `MAX_CONCURRENT_JOBS` | `1` | число одновременных заданий |
| `BATCH_COLLECT_SECONDS` | `4` | пауза, после которой пачка файлов считается полученной; `0` — каждый файл отдельно |
| `STRIP_WORD_COMMENTS` | `true` | удалять примечания Word на полях |
| `DETECT_TABLES` | `true` | восстанавливать таблицы с границами |
| `OCR_DESKEW` | `true` | выравнивать наклон страницы перед OCR |
| `TEMP_DIR` | `./temp` | каталог временных файлов |
| `LOG_LEVEL` | `INFO` | уровень логирования |

Выбор режима (кнопка «⚙️ Режим проверки» или `/mode`) сохраняется для каждого пользователя
в `DATA_DIR/user_modes.json` и переживает перезапуск. Если `DATA_DIR` пуст, режим хранится
в памяти и сбрасывается к `AI_VALIDATION_MODE`. При росте числа пользователей стоит перейти на БД.

## Запуск

```bash
cd /opt/ocr_telegram_bot
sudo -u ocrbot .venv/bin/python -m app.bot
```

## Тесты

```bash
.venv/bin/pytest -q                       # модульные и интеграционные тесты с моками (~10 с)
RUN_OCR_TESTS=1 .venv/bin/pytest -q -m ocr  # с настоящим PaddleOCR: русский, английский, 2-страничный PDF
```

Тесты не требуют токена Telegram и не обращаются к OpenAI. OCR-тестам нужен шрифт с кириллицей
(в Ubuntu: `sudo apt install fonts-dejavu-core`).

Тестами покрыты: схема ответа ИИ, DOCX в обоих режимах, отклонение неподдерживаемых и
повреждённых файлов, лимиты размера, страниц и пикселей, выбор режима ИИ и поведение без ключа,
сбой внешнего API, очистка временных файлов, обработчики Telegram (с моками и через `Dispatcher`),
allowlist, маскирование секретов в логах.

## Развёртывание через systemd

```bash
sudo -u ocrbot mkdir -p /home/ocrbot/.paddlex
sudo cp deploy/ocr-telegram-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now ocr-telegram-bot
sudo journalctl -u ocr-telegram-bot -f
```

Проверьте, что бот поднимается после перезагрузки: `sudo reboot`, затем
`systemctl status ocr-telegram-bot` и `/start` в Telegram.

## Развёртывание через Docker

```bash
cp .env.example .env && nano .env
docker compose up -d --build
docker compose logs -f
docker compose run --rm bot pytest -q   # тесты внутри контейнера
```

Временный каталог в контейнере — `tmpfs` (в RAM, исчезает при остановке), модели PaddleOCR
хранятся в volume `paddle-models`.

## Временные файлы и политика хранения

- Каждое задание получает отдельный каталог `TEMP_DIR/job_*`. В нём лежат скачанный файл,
  PNG-страницы и итоговый DOCX.
- Исходный файл удаляется сразу после разбивки на страницы, весь каталог — в `finally` после
  отправки результата или при любой ошибке.
- При запуске бот удаляет каталоги `job_*` старше часа, оставшиеся после аварийной остановки.
- Документы и результаты долговременно не хранятся. Содержимое документов в лог не пишется:
  в логе только технические события (номер страницы, число фрагментов, время, тип ошибки).
- `temp/` исключён из Git.

## Безопасность

- `.env` не коммитится (`.gitignore`); права на файл — `600`.
- Токены и ключи маскируются в логах, включая stack trace. Пользователь видит только понятные
  сообщения, без технических деталей.
- Для конфиденциальных документов обязательно задайте `ALLOWED_TELEGRAM_USER_IDS`.
- В режимах `text`/`image` текст и изображения страниц передаются внешнему провайдеру (OpenAI).
  До включения AI-проверки согласуйте требования к персональным и конфиденциальным данным
  (раздел 13 ТЗ, вопрос 2).
- Telegram Bot API позволяет боту скачивать файлы только до 20 МБ. Чтобы поднять `MAX_UPLOAD_MB`
  выше 20, нужен собственный Bot API server.

## Совместимость PaddleOCR

Проверено: `paddlepaddle==3.3.1`, `paddleocr==3.7.0` на CPU. Выявленные особенности:

1. **oneDNN.** На PaddlePaddle 3.3 CPU-инференс с oneDNN падает с
   `NotImplementedError: ConvertPirAttribute2RuntimeAttribute not support`, поэтому по умолчанию
   `OCR_ENABLE_MKLDNN=false`. На целевом VPS можно попробовать `true`: это ускоряет работу,
   если ошибка не воспроизводится.
2. **Модель детекции.** Серверная `PP-OCRv5_server_det` без oneDNN обрабатывает страницу A4
   примерно за 2 минуты, мобильная `PP-OCRv5_mobile_det` — примерно за 7 секунд при сопоставимом
   качестве на печатном тексте. По умолчанию используется мобильная.
3. **Язык.** Если имена моделей заданы явно, PaddleOCR 3.x игнорирует параметр `lang`. Поэтому
   модель распознавания выбирается по `OCR_LANGUAGES` явно: для `ru` — `eslav_PP-OCRv5_mobile_rec`
   (кириллица и латиница), для `en` — `en_PP-OCRv5_mobile_rec`.

Замеры выше сделаны на рабочей станции. Время и качество на целевом VPS нужно зафиксировать
на согласованной контрольной выборке (CER/WER, раздел NFR-05 ТЗ).
